Defense-in-depth governance for RAG pipelines.

We don’t block data. We govern its safe flow.

Bastion RAG is a modular security architecture that wraps Retrieval-Augmented Generation pipelines in both directions — screening queries, anonymizing PII, enforcing pre-search tenant isolation, protecting embeddings on the way in, and verifying grounding and permissions on the way out.

Author’s Note Why I started this repository

I started Bastion RAG to study AI and systems security from first principles. Rather than treating LLM security as a single prompt wrapper, I wanted to design, implement, and test concrete controls across the entire retrieval lifecycle: prompt-injection heuristics, format-preserving PII tokenization, pre-filter tenant isolation, differential privacy on embeddings, HMAC-chained audit logs, and mTLS/JWT zero-trust service boundaries. Threat Model

Connecting private corpora to an LLM introduces failure modes across input parsing, retrieval, vector storage, and generation. Each layer in Bastion addresses a distinct threat class.

  • Injection Prompt & Indirect Injection Adversarial instructions in user queries or retrieved documents override system instructions. Mitigation: Sentinel-IN + Contextual Document Scan
  • Privacy PII & Secret Exposure Names, SSNs, emails, or credentials enter third-party LLM prompts or leak in model completions. Mitigation: Vault Two-Phase Tokenization + Sentinel-OUT
  • Isolation Cross-Tenant Data Leakage Post-search filtering in shared vector indexes leaks document existence across tenant boundaries. Mitigation: Navigator Pre-Filter + Vault JWT Tenant Binding
  • Vectors Embedding Inversion & Bias Compromised float vectors reconstruct source text, or skewed representations bias answers. Mitigation: Anchor Differential Noise + WEAT Audit
  • Integrity Hallucination & Ungrounded Claims The model fabricates figures, citations, or claims unsupported by the retrieved context. Mitigation: Sentinel-OUT Grounding & Citation Verifier
  • Intrusion Reconnaissance & Insider Probing Attackers query planted decoy identifiers, signaling credential theft or corpus exfiltration. Mitigation: Cross-Layer Honey-Tokens + Tracker Alerts

Core Modules

Go

Sentinel

Bidirectional validation gateway

First and last line of defense. Detects prompt injection (regex, keyword rules, and logistic ML scoring) on input; catches PII re-emergence, Vault token-map leaks, hallucinations, and permission violations on output.

~0.3 ms in · ~0.9 ms out · REST & gRPC TLS

Documentation
Go

Vault

Two-phase privacy & tokenization

Replaces 30+ PII entity types with deterministic tenant-scoped tokens before the LLM sees them, enforces K-anonymity and RBAC/OPA policies, and restores values only for authorized callers.

Tokenize → Process → Detokenize

Documentation
Python + Go

Navigator

Tenant-isolated hybrid retrieval

Filters by tenant before vector search, never after. Rewrites Vault tokens for searchability, fuses BGE-M3 dense and BM25 sparse results with RRF, reranks, and federates with hop-depth loop prevention.

Pre-filter isolation · RRF fusion

Documentation
Python

Anchor

Embedding security & fairness

Adds calibrated Gaussian or Laplace differential privacy noise to embeddings on the unit hypersphere so compromised vectors cannot invert source text, and audits demographic bias via WEAT statistics.

Differential privacy noise · WEAT

Documentation
Go + React

Tracker

Audit lineage & human-in-the-loop

Correlates every stage into an HMAC-signed, tamper-evident audit chain. Switch at runtime between off, observe, and gate modes where operators review sensitive pipeline checkpoints.

HMAC-SHA256 audit · Lineage UI

Documentation
Cross-Cutting

Defense in Depth

Honey-tokens · mTLS · Zero-trust

Planted decoy records expose intruders across three independent layers. Every service authenticates callers via Bearer/JWT tokens and supports hot-reloaded TLS and mutual TLS (mTLS) on gRPC.

Fail-closed defaults · Live cert reload

05

Security Engineering Study Notes

This repository was built to study AI and distributed-systems security by implementing concrete mechanisms rather than relying on black-box wrappers. Below are the six core areas explored across the codebase.

Area 01

Adversarial Prompt & Output Defense

Explored how Unicode homoglyphs, delimiter escapes (<|im_start|>), and indirect document injections bypass naive filters — combining NFC normalization, regex/keyword rules, logistic feature scoring, and outbound grounding verification.

Area 02

Privacy-Preserving Data Flows

Studied the trade-off between utility and privacy when sending context to external LLMs: AES-GCM vault storage, format-preserving tokens, K-anonymity cohort checks (k ≥ 5), and cross-referencing Vault mappings on LLM output.

Area 03

Multi-Tenant Isolation & Federation

Investigated how post-filtering in vector databases leaks the existence of other tenants’ documents, implementing strict pre-filter tenant scoping, Vault permission intersections, and hop-limited peer federation.

Area 04

Vector Inversion & Algorithmic Fairness

Studied embedding inversion attacks (reconstructing text from raw float vectors) and implemented L2-normalized Gaussian/Laplace noise injection alongside Word Embedding Association Test (WEAT) bias measurement.

Area 05

Zero-Trust Service-to-Service Security

Practiced eliminating implicit internal trust: every REST and gRPC server enforces caller authentication (JWT/RBAC or constant-time bearer tokens), fail-closed startup validation, and live-reloaded TLS/mTLS certificates.

Area 06

Tamper-Evident Auditing & Deception

Implemented cryptographic hash-chained audit logs (HMAC-SHA256) to detect log tampering, cross-module honey-token tripwires for intrusion detection, and interactive human-in-the-loop approval gates.
