ORIGIN NOTE // WHY I STARTED THIS REPOSITORY

I started Bastion-RAG as a hands-on project to study security engineering in the era of AI & Retrieval-Augmented Generation. Rather than treating LLM security as a single prompt filter, I wanted to build and test every layer from first principles: prompt-injection heuristics, format-preserving PII tokenization, pre-filter tenant isolation, differential privacy on vectors, HMAC-chained audit logs, and mTLS/JWT zero-trust service boundaries. 01 THREAT MODEL

Feeding private documents to an LLM creates a multi-layer attack surface. Each threat requires a dedicated control.

  • INJECTION Prompt & Indirect Injection Hidden instructions in user queries or retrieved documents hijack model behavior. Countered by: Sentinel-IN + Contextual Doc Scan
  • PRIVACY PII & Secret Leakage Names, SSNs, emails, or API keys slip into prompts or re-emerge in LLM completions. Countered by: Vault Two-Phase Tokenization + Sentinel-OUT
  • ISOLATION Cross-Tenant Exposure Customer A’s vectors or records surface for Customer B on shared infrastructure. Countered by: Navigator Pre-Filter + Vault JWT Tenant Binding
  • VECTOR Embedding Inversion & Bias Stolen embeddings reconstruct source text, or skewed representations bias answers. Countered by: Anchor Differential Noise + WEAT Analyzer
  • INTEGRITY Hallucination & Drift The model states ungrounded numbers or facts absent from retrieved context. Countered by: Sentinel-OUT Grounding & Citation Verifier
  • INTRUSION Reconnaissance & Insider Probing Attackers query specific decoy records proving prior unauthorized access. Countered by: Cross-Layer Honey-Tokens + Tracker Alerts

SENTINEL

Bidirectional validation gateway

First and last line of defence. Detects prompt injection (regex + keyword + logistic ML scorer) on the way in; catches PII re-emergence, Vault token-map leaks, hallucinations and permission violations on the way out.

VAULT

Two-phase privacy shield

Replaces 30+ PII entity types with deterministic tenant-scoped tokens before the LLM sees them, enforces K-anonymity & RBAC/OPA policies, and restores values only for authorized callers.

05 SECURITY STUDY LOG

This repository was built to study AI and distributed-systems security by implementing real controls rather than relying on black-box wrappers. Here are the six core security domains explored across the codebase:

STUDY // 01

Adversarial Prompt & Output Defense

Explored how Unicode homoglyphs, delimiter escapes (<|im_start|>), and indirect document injections bypass naive filters — combining NFC normalization, regex/keyword rules, logistic feature scoring, and outbound grounding verification.

STUDY // 02

Privacy-Preserving Data Flows

Studied the trade-off between utility and privacy when sending context to external LLMs: AES-GCM vault storage, format-preserving tokens, K-anonymity cohort checks (k ≥ 5), and cross-referencing Vault mappings on LLM output.

STUDY // 03

Multi-Tenant Isolation & Federation

Investigated how post-filtering in vector databases leaks existence of other tenants’ documents, implementing strict pre-filter tenant scoping, Vault permission intersections, and hop-limited peer federation.

STUDY // 04

Vector Inversion & Algorithmic Fairness

Studied embedding inversion attacks (reconstructing text from raw float vectors) and implemented L2-normalized Gaussian/Laplace noise injection alongside Word Embedding Association Test (WEAT) bias measurement.

STUDY // 05

Zero-Trust Service-to-Service Security

Practiced eliminating implicit internal trust: every REST and gRPC server enforces caller authentication (JWT/RBAC or constant-time bearer tokens), fail-closed startup validation, and live-reloaded TLS/mTLS certificates.

STUDY // 06

Tamper-Evident Auditing & Deception

Implemented cryptographic hash-chained audit logs (HMAC-SHA256) to detect log tampering, cross-module honey-token tripwires for intrusion detection, and interactive human-in-the-loop approval gates.
