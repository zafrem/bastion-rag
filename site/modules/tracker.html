TRACKER

Observability and human-in-the-loop

  • Go + React
  • REST/UI :8080 · gRPC :9090 · WebSocket :8081

An observer: it touches no data in the pipeline, but records everything that happens to it.

01 OVERVIEW

Tracker is the control center. Every module emits standard events tagged with a trace_id, and Tracker turns them into a lineage you can query, an HMAC-signed audit log, and a live operator dashboard.

02 WHAT IT DOES

  • Real-time flow visualization over WebSocket, with an embedded operations dashboard.
  • Tamper-evident audit log: events are HMAC-signed as they are stored.
  • Data lineage queryable by trace_id, user_id or audit scope.
  • Honey-token detection and rule-based alerts with incident management.
  • Pipeline monitoring modes switchable at runtime: off, observe and gate (human approval at each stage, rejecting on timeout by default).
  • Anomaly detection and bypass monitoring.

03 WHERE IT SITS

PathRole
InputCollects events from every module on the way in, correlating them under a single trace_id.
OutputDoes the same on the way out, so one request's full journey can be reconstructed afterwards.

04 RUN IT

export TRACKER_AUDIT_SECRET=$(openssl rand -hex 32)   # >= 32 bytes, required
cd tracker && make run   # or: make start-tracker from the repo root
# dashboard: http://localhost:8080

05 EXAMPLE: SWITCH TO GATE MODE AND APPROVE A CHECKPOINT

# Every pipeline stage now waits for human approval
curl -X POST http://localhost:8080/v1/monitor/mode \
     -d '{"mode": "gate", "reason": "incident investigation"}'

# An operator approves a pending checkpoint
curl -X POST http://localhost:8080/v1/monitor/checkpoints/{id}/decide \
     -d '{"decision": "approve", "notes": "verified — legitimate request"}'

Real-time updates are pushed over WebSocket, so dashboards update without polling.

06 SECURITY SETTINGS

storage:
  audit_secret: ""     # required, >= 32 bytes (env TRACKER_AUDIT_SECRET)
auth:
  enabled: false
  jwt_secret: ""       # required when auth is enabled (env TRACKER_JWT_SECRET)
server:
  cors_allowed_origins: []   # empty = no CORS headers
  trust_proxy: false
dev_mode: false        # skips the startup checks; local demos only

Defaults. Tracker refuses to start without an audit secret, because signatures made with a public key are forgeable. With auth enabled it also needs a real JWT secret and bcrypt-hashed passwords.
