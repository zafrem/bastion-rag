VAULT

Two-phase privacy shield

  • Go
  • REST :8081 · gRPC :9091

The model never sees real personal data. Vault tokenizes on the way in and restores values, for authorised users only, on the way out.

01 OVERVIEW

Vault replaces sensitive values with structured tokens before the query reaches the LLM, and decodes them after the response returns according to each user's access level. Tokens are scoped per tenant, so the same token in two tenants maps to different values.

02 WHAT IT DOES

  • PII detection across 30+ entity types: names, emails, phone numbers, national IDs and financial data.
  • Structured tokens in the [TYPE_hex6] shape, scoped per tenant.
  • Access control with built-in RBAC and optional OPA (Rego) policy delegation.
  • K-anonymity enforcement and selective detokenization per user.
  • Key management through a KMS abstraction (local, AWS, HashiCorp Vault).
  • Break-glass access requests with approval, plus a cloud LLM connector that anonymizes payloads before they leave your network.

03 WHERE IT SITS

PathRole
InputPhase 1 anonymizes the query: PII becomes tenant-scoped tokens, and decoy (honey-token) values are flagged.
OutputPhase 2 applies access policy to the response and detokenizes only the fields the user is allowed to see.

04 RUN IT

export VAULT_AUTH_JWT_SECRET=$(openssl rand -hex 32)   # >= 32 bytes, required
export VAULT_KMS_LOCAL_MASTER_KEY=$(openssl rand -hex 32)
cd vault && go run ./cmd/vault server -c configs/vault.yaml   # or: make start-vault from the repo root

05 EXAMPLE: ANONYMIZE RECORDS

POST /v1/vault/anonymize
Authorization: Bearer <token>
Content-Type: application/json

{
  "category": "DC-01",
  "records": [
    {"name": "김철수", "rrn": "850101-1234567", "mobile": "010-1234-5678"}
  ],
  "purpose": "analytics",
  "requester_id": "user-abc",
  "access_level": "anonymized"
}

Every endpoint except health and metrics requires a Bearer JWT; send X-Tenant-ID to select a tenant.

06 SECURITY SETTINGS

auth:
  jwt_secret: ""                # required, >= 32 bytes (env VAULT_AUTH_JWT_SECRET)
  jwt_algorithm: HS256
  skip_auth: false              # dev only
  revocation_fail_open: false   # Redis outage -> 503, not accepted

Defaults. Vault refuses to start with an empty, short or placeholder JWT secret (unless skip_auth is on, for development only). Token revocation fails closed: if the Redis revocation list can't be queried, requests get 503.
