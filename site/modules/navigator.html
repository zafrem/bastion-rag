NAVIGATOR

Tenant-isolated hybrid search

  • Python
  • REST :8082 · gRPC :9092

Retrieval that never touches another tenant's data, not even transiently.

01 OVERVIEW

Navigator is the search and ranking layer. It applies the tenant filter before the search runs rather than filtering results afterwards, then fuses vector and keyword results and reranks them. It integrates with Qdrant for vector storage and uses BGE-M3 embeddings for Korean and English.

02 WHAT IT DOES

  • Pre-filter isolation: tenant metadata filters are applied before the search, not after.
  • Hybrid search: HNSW vector search combined with BM25 using Reciprocal Rank Fusion (RRF).
  • Reranking with a BGE cross-encoder.
  • Access-aware filtering through Vault, based on user permissions and data categories.
  • Multilingual retrieval tuned for mixed Korean and English document sets.
  • Federated search across deployments, with a hop-depth counter to prevent circular queries.

03 WHERE IT SITS

PathRole
InputEmbeds the query, runs tenant-scoped hybrid search, fuses and reranks the results, and filters by permission.
OutputNavigator sits on the retrieval side of the pipeline; the output checks are done by Anchor, Vault and Sentinel.

04 RUN IT

cd navigator
make install && make run   # or: make start-navigator from the repo root

Note. With Vault enabled, Navigator authenticates to Vault with a service JWT (vault.auth_token_file or NAVIGATOR_VAULT_AUTH_TOKEN) and sends the user's department and roles, so Vault decides for the user. If Vault can't be reached or rejects the token, Navigator searches no collections instead of all of them. On first run Navigator downloads the BAAI/bge-m3 (~1.4 GB) and BAAI/bge-reranker-v2-m3 (~900 MB) models, which are cached afterwards. It needs about 4 GB of RAM.
